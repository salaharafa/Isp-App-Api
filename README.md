# IspAppApi – نظام إدارة مزود خدمة الإنترنت

## نبذة عن المشروع

مشروع **ASP.NET Core Web API** تدريبي وتطبيقي يحاكي نظاماً لإدارة مزود خدمة الإنترنت (ISP)، ويهدف إلى تطبيق مفاهيم تطوير الـ Backend وتنظيم الكود باستخدام Clean Architecture وCQRS، مع تطبيق قواعد عمل تحاكي سيناريوهات واقعية.

المشروع قيد التطوير، وليس نظاماً تجارياً جاهزاً للاستخدام الفعلي.

## الوحدات الرئيسية

- **Customers:** إدارة العملاء.
- **Service Plans:** إدارة باقات الإنترنت.
- **Subscriptions:** إدارة اشتراكات العملاء.
- **Bills:** إدارة الفواتير.
- **Payments:** تسجيل المدفوعات وإلغاؤها.
- **Tickets:** إدارة تذاكر الدعم الفني.
- **Hardware:** إدارة الأجهزة.

## قواعد العمل (Business Rules)

### 1. الاشتراكات (Subscriptions)

- يمكن للعميل امتلاك أكثر من اشتراك نشط في الوقت نفسه.
- الاشتراك مستمر بطبيعته، ولا يتطلب تحديد تاريخ انتهاء مسبقاً؛ حيث يكون `EndDate` فارغاً حتى إلغاء الاشتراك.
- تعليق الاشتراك بسبب وجود فواتير غير مدفوعة لا يعني إلغاءه، ويمكن استئناف الاشتراك المعلق وإعادته إلى حالة `Active`.
- الباقات المعطلة لا تظهر ضمن الباقات المتاحة لإنشاء اشتراكات جديدة، بينما تستمر الاشتراكات الحالية المرتبطة بها.
- لا يمكن تغيير الباقة المرتبطة باشتراك قائم؛ ويتم تغيير الباقة من خلال إلغاء الاشتراك السابق وإنشاء اشتراك جديد، مع الحفاظ على السجلات التاريخية.

### 2. الفواتير والمدفوعات (Bills & Payments)

- الحفاظ على السجلات المالية التاريخية ومنع تعديل مبلغ الدفعة أو تاريخها بعد تسجيلها.
- عند الحاجة إلى تصحيح دفعة، يجب إلغاؤها وتسجيل دفعة بديلة بدلاً من تعديل بياناتها.
- إجمالي الفاتورة (`TotalAmount`) غير قابل للتعديل بعد إنشائها، بينما يمكن تعديل تاريخ الاستحقاق (`DueDate`).
- عند إلغاء دفعة، يتم تحديث حالة الفاتورة تلقائياً إلى `Unpaid` إذا لم تعد هناك دفعات فعّالة مرتبطة بها.

### 3. تذاكر الدعم الفني (Tickets)

- تبدأ كل تذكرة جديدة بالحالة `New` تلقائياً.
- تبدأ معالجة التذكرة من خلال عملية مستقلة تنقلها من `New` إلى `InProgress`.
- لا يمكن إغلاق التذكرة إلا بعد بدء معالجتها، وذلك بنقلها من `InProgress` إلى `Closed`.
- يمكن إعادة فتح التذكرة المغلقة ونقلها من `Closed` إلى `InProgress`.
- يُسمح بحذف التذاكر التي لا تزال بحالة `New` فقط، مع الحفاظ على سجلات التذاكر التي بدأت معالجتها أو أُغلقت.
- تم فصل تعديل بيانات التذكرة عن تغيير حالتها؛ فتعديل البيانات لا يسمح بتغيير `Status`، ولكل انتقال في دورة الحياة عملية مستقلة.

## المصادقة (Authentication)

يستخدم المشروع JWT Authentication لحماية نقاط النهاية (Endpoints) التي تتطلب تسجيل الدخول.

توجد حالياً بيانات دخول إدارية تجريبية، ويجب ضبطها ضمن إعدادات التطبيق قبل التشغيل.

## الاختبارات (Testing)

## تشغيل المشروع

### المتطلبات

- .NET 9 SDK
- SQL Server

### تحميل المشروع

```powershell
git clone https://github.com/salaharafa/Isp-App-Api.git
cd Isp-App-Api
cd IspAppApi
```

### إعداد قاعدة البيانات

اضبط Connection String في إعدادات التطبيق باستخدام المفتاح:

`ConnectingStrings:IspAppDbConnectionString`

ثم تأكد من إعداد بيانات الدخول الخاصة بالمصادقة قبل تشغيل التطبيق.

### تشغيل التطبيق

```powershell
dotnet run --project IspAppApi
```

### تشغيل الاختبارات

```powershell
dotnet test
```
